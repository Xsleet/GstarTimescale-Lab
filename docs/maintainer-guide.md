# 维护者指南：公开接口与独立运行包

## 三部分分别保存

| 部分 | 保存位置与分发范围 |
|---|---|
| 核心源码、开发历史、编译配置 | 原私有工程，只有核心开发者访问 |
| 教程、输入生成、公开配置、分析、测试 | 本公开仓库，任何人可阅读 |
| 经审查的公开实验数据 | 独立数据 Release，仓库保留清单、SHA256 和复现入口 |
| 编译程序、运行所需组件、第三方声明 | 维护者保管的独立 ZIP，只发给授权用户 |

实验仓库使用独立 Git 历史，没有从源码仓库直接 fork 或改公开可见性。不要把源码仓库转为公开，也不要把私有历史合并到这里。

## 版本配套与分发

授权用户需要本仓库链接、匹配版本的 `GstarTimescale-engine-0.1.0-windows-x64.zip`，以及 README 使用步骤。运行包通过受控渠道单独分发；本项目没有建立在线下载服务、用户账号系统或授权服务器。

程序 ZIP 包含 `GstarTimescale.exe`、使用说明、第三方许可和受许可要求提供的第三方源码包。第三方源码包仅对应 Eigen 依赖，不包含 GSTAR 私有求解源码。不要删掉随包许可证，也不要把“核心不公开”误解为可以省略第三方声明。

公开的 `engine-release.json` 只有版本、文件名、大小与 SHA256，不包含程序。哈希用于发现错版、传输损坏和文件变动；它不是数字签名、身份认证或防拷贝机制。用户应同时信任公开仓库来源和维护者发包渠道。

## 更新程序版本

在私有开发环境完成算法开发和回归，再制作独立 Release 程序包。剥离调试符号，检查依赖与本机路径，保留适用的第三方声明和源码提供方式。将构建日志、源码提交号、编译参数放在私有档案中，不发布到实验仓库。

每次发包使用新版本号，重新生成 `engine-release.json`。公开仓库、程序 ZIP 和研究记录必须匹配。保持旧版公开 Git 标签与旧版私有 ZIP 可配对，便于复现用户结果。

在没有私有源码、没有编译器 PATH 的干净目录中验证：安装 → doctor → 单元测试 → 10 天实验 → 五线 ADEV → 日志和输入数量检查。分布式或新案例需单独记录验证范围。

## 防止误公开

本仓库默认忽略 engine、Runs、二进制、库文件和压缩包，并有 Git 索引检查脚本。可选择为这个本地仓库启用提交钩子：

```powershell
git config core.hooksPath .githooks
```

提交前还应显式检查：

```powershell
git status --short
git diff --cached --stat
python tools/check_public_tree.py
```

检查读取的是 Git 索引，不会把本机忽略的程序包读进 Git。规则只允许公开文件路径和文本类型，并检查部分常见凭证和本机路径模式。它不是通用秘密扫描器，无法识别所有改名、编码或人为绕过；仍需人工审核内容。CI 在推送后运行，不能撤销已经发生的泄露。

公开 CI 测试 Python 工具、合成测试夹具，以及明确公开的论文归档数据；不获取核心程序、不访问私有源码仓库、不上传程序包。不要为公共工作流配置私有源码访问令牌，也不要用公开 Release 存放受限分发的程序 ZIP。

论文数据 Release 与程序分发分开管理。第 4.3 节仅公开相位、协方差、CLK/PFD、配置及来源记录；ZIP 不进入 Git 历史。发布前逐文件检查数据范围、机器路径、凭证、源码和可执行文件，写入每个文件及整个 ZIP 的校验值；上传后从公开下载地址验证。修改数据使用新版本号和新文件名，不覆盖已有复现实验依赖的同名文件。保留差异表和失败记录，不因图表能画出就标记全部论文结果复现成功。

## 本方案解决到什么程度

公开接口覆盖实验配置与分析，核心 C++ 源码不会随仓库交付。可执行文件仍可复制或被逆向分析。本仓库未新增 DRM 或远程授权功能；核心已有的起始年份范围限制见 [配置指南](configuration.md)。分发政策不限制第三方组件依法享有的权利。

如果未来要求核心程序也不能到用户电脑，需要改为你控制的服务器计算服务；那是另一种部署方案，不是当前的离线实验包。
